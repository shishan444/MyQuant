# 退役清理 SOP（子系统/端点/模块退役标准操作清单）

> 来源：fix-replay-gap-alignment 2.7 防再生条款（2026-11-21）——把
> retire-legacy 战役中实际遵循的退役步骤固化为操作清单，并增补**缓存
> 清理**一步。纯文档（不建新机制）；每次退役类 change 的 tasks 收尾
> 段按本清单逐项对照执行。

## 适用对象

子系统整域退役（如 retire-legacy 的 evolution/live/旧验证）、端点族
退役（如孤儿端点清理）、模块级删除（符号/文件级退役）。

## 标准步骤（按序执行，每步有可验证完成标准）

1. **删除面界定**：以消费面全域检索为权威（前端 web/src+MCP
   mcpserver+测试域三面），零消费=可删；「前端改指/承接」类出路须
   先核实契约逐参兼容（同源计算≠接口等价）。
2. **代码删除**：按域成组删除（不逐处抠调用）；死区数据流闭包内
   状态/hook/组件随死区走。
3. **路由与导航收口**：路由项+菜单项+入口引用同批删；删除路由后
   必须收口导航（catch-all 重定向到现役主页，防旧书签空白页）。
4. **测试资产分拣**：守护对象消失的专属测试随删；混装文件按用例
   拆；守护对象存活者改指不改断言；交付附删/增用例数对账表。
5. **对账断言同步**：退役端点并入 404 点名清单（tests/api/
   test_retired_endpoints_404.py）+openapi.json 再生成（端点终态后
   一次到位——恢复类端点先恢复再生成，防基准失真）。
6. **缓存清理（本 SOP 增补——2026-11-21）**：退役删除域后按域路径
   整目录删 `__pycache__`，判据驱动不点名文件：
   ```bash
   find <退役域路径> -name __pycache__ -type d -exec rm -rf {} +
   ```
   孤儿 .pyc 判据=对应源 .py 既无同名文件也无同名包目录（源已删
   的缓存即孤儿）。git 索引零 .pyc（.gitignore 已含），本步清理的
   是工作区运行时残留——防检索误报与「注释当现状」类误导。
7. **残留审计**：整删模块用模块级词全域清零检索；拆分模块用符号
   级词审已删符号（保留面符号不属审计对象）。
8. **留档**：删除决策与重评估条件落 change 文档/TD 台账（不进
   RETAINED_ENDPOINTS——该表只登记「活着且无人到达但有明示理由」
   的保留面）。

## 与本仓既有设施的关系

- `.gitignore` 已含 `__pycache__/`+`*.py[cod]`（仓库卫生无缺口，
  缓存清理关注工作区非仓库）。
- 端点保留登记表 `tests/api/_endpoint_registry.py`（T5 对账的机读
  保留面）与退役 404 清单（运行时证明）互补，均不承载删除留档。
